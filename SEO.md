# SEO — what is in the code, and what only you can do

Everything in **Part 1** is implemented and building. **Part 2** needs your Google
account and your phone; nobody can do it from inside the repo.

---

## Part 0 — read this first: why Google is not showing the site

The technical problems listed below were real, but none of them was the main one.
Two things matter more:

1. **The site is client-side rendered.** `index.html` ships an empty
   `<div id="root">`. Google *can* execute JavaScript, but it does so on a second
   pass that can lag days or weeks behind the first crawl, and it is the first
   thing to be dropped for a site with no authority yet. Every heading, every
   paragraph and every case study on your home page currently exists only after
   React runs.
2. **The site is new and nothing links to it.** Google will not rank a domain it
   has never seen referenced anywhere. This is Part 2, and it is the slower half.

The head of `index.html` is now fully populated *statically* — title, description,
canonical, Open Graph, and the JSON-LD graph are all in the raw HTML, so a crawler
gets them with JavaScript switched off. That closes most of the gap. If, after
4–6 weeks in Search Console, the page is indexed but ranking poorly for its own
brand name, the next step is **prerendering** — see "Known remaining gap" below.

Realistic timeline: indexed in **3–14 days** after you submit the sitemap; ranking
for "eZentix Labs" in **2–6 weeks**; ranking for competitive terms like
"billing software for shops West Bengal" in **4–8 months**, and only with Part 2.

## Part 1 — implemented

| Item | Where |
|---|---|
| `sitemap.xml` | `client/public/sitemap.xml`, generated by `client/tools/gen-sitemap.mjs` on every `npm run build` |

| Alt text | founder portrait now names the person *and* their role; case-study cover describes the image; the four gallery screens no longer share one identical alt |
| Internal links | new crawlable `<nav>` in `TopBar.jsx` linking all five sections. The header previously contained zero links besides the logo |
| Broken links | `href="#"` on the invoice download is now a disabled button; five placeholder social links to bare `youtube.com` / `instagram.com` / etc. removed |

| HTTPS | HSTS `max-age=63072000; includeSubDomains; preload` in `vercel.json`, plus nosniff, Referrer-Policy and X-Frame-Options |
| URL slugs | only two routes exist (`/` and `/account`) and both are already clean. `cleanUrls` and `trailingSlash: false` set in `vercel.json` so one URL never resolves two ways |
| Mobile | checked at 375 px: no horizontal scroll, no overflowing element |

### One thing to do in the Vercel dashboard

Pick **one** of `ezentixlabs.com` or `www.ezentixlabs.com` as the primary domain
and let Vercel 308 the other to it. The canonical tags all point at the apex
(`https://ezentixlabs.com/`), so make the apex primary unless you have a reason
not to. Two hosts both serving 200 is a duplicate-content split.

### Changing the domain later

`client/src/seo/site.js` is the only file with the origin in it. Change `ORIGIN`
there, run `npm run seo`, and update the absolute URLs in `client/index.html`.

### Known remaining gap: prerendering

If you want the strongest possible position, render the home page's HTML at build
time. With one public route the cheapest route is `vite-plugin-prerender` or
`react-snap` in the build step — the output stays a static site on Vercel, but
crawlers get the real copy on the first pass instead of the second. It was left
out here because it pulls in a headless Chromium and changes how the build runs,
which is your call to make, not a change to slip in unannounced.

## Part 2 — only you can do these

### A. Verify Google Search Console (20 minutes, do this today)

This is the single highest-value thing left, because until it is done you are
guessing about whether Google can see the site at all.

1. Go to <https://search.google.com/search-console> and sign in.
2. Choose **Domain** property (not URL prefix) and enter `ezentixlabs.com`.
   A Domain property covers http, https, apex and www in one go.
3. Google gives you a **TXT record**. Add it at your domain registrar under DNS:
   - Type: `TXT`, Name/Host: `@`, Value: the `google-site-verification=...` string
   - If your DNS is on Vercel: Project → Settings → Domains → your domain → DNS Records.
4. Wait 5–30 minutes for propagation, then click **Verify**.
5. Once verified: **Indexing → Sitemaps**, submit `sitemap.xml`.
6. **URL Inspection**, paste `https://ezentixlabs.com/`, click **Request Indexing**.
7. Come back in 3 days. In URL Inspection use **View crawled page → Screenshot**.
   If the screenshot shows your real home page, JavaScript rendering is working.
   If it shows a blank page, do the prerendering work above.

> If you would rather not use DNS, the alternative is HTML file verification:
> Google gives you a `googleXXXX.html` file — drop it in `client/public/` and
> redeploy. DNS is better because it survives a hosting change.

**Do the same for [Bing Webmaster Tools](https://www.bing.com/webmasters).** It
takes five minutes, it can import directly from Search Console, and Bing feeds
DuckDuckGo and increasingly ChatGPT's search.

### B. Google Business Profile — do this before any link building

For a local service business in Budbud, this outranks almost everything else on
this page. A verified Business Profile is what puts you in the map pack and in
"IT company near me" searches, and it is free.

1. <https://business.google.com> → add your business.
2. Category: *Software company* (primary), plus *Website designer*,
   *Business management consultant*.
3. Service area: Budbud, Panagarh, Durgapur, Bardhaman — wherever you actually travel.
4. Verification is usually by postcard to the address, so start it early; it takes
   1–2 weeks.
5. Put `https://ezentixlabs.com` in the website field. **This is itself a backlink**,
   and it is the first one Google will find.
6. Post to it weekly. A Business Profile that goes quiet stops being shown.

Once the profile is live, add the address you verified with into the
`PostalAddress` block in `client/index.html` — `streetAddress` and `postalCode`
were deliberately left out rather than guessed, and the schema should match the
profile character for character.

### C. Backlink strategy

The honest framing: you need roughly 10–20 genuine, relevant links before Google
treats the domain as real. You are not going to buy your way there, and you
should not try — link schemes are the one SEO mistake that carries a manual
penalty.

**Tier 1 — free, this week, no permission needed (aim: 8 links)**

| Where | Note |
|---|---|
| Google Business Profile | as above — do it first |
| Bing Places | same, 10 minutes |
| JustDial, Sulekha, IndiaMART | the three that matter in India for B2B services |
| LinkedIn company page | fill it out properly and link the site |
| Facebook and Instagram business profiles | the site's footer social list is empty until these exist — create them, then put the real URLs back in `content.js` *and* add them to a `sameAs` array in the JSON-LD |
| Your own LinkedIn profile | Sourav's decade at Tech Mahindra, Capgemini and LTIMindtree is a genuine credibility asset; the "Experience" entry for eZentix Labs should link the site |
| Startup India registry / India business directories | Startup India registration is free and the listing is indexed |

**Tier 2 — your existing customers (aim: 3–10 links, highest quality on this page)**

This is your real advantage and it costs nothing:

- Every client site you build should carry a **"Website by eZentix Labs"** link in
  its footer, pointing at `https://ezentixlabs.com`. Kulhad Chai and Pizza Cafe is
  one already. Put it in your standard contract so it is not a conversation each time.
- Ask each client to mention you in their own Google Business Profile posts.
- Ask for a Google review on your Business Profile. Reviews are not backlinks, but
  for local search they move the needle harder than most links do.

Ten clients at one footer link each is ten relevant, topically-aligned,
geographically-local links. No agency can sell you better than that.

**Tier 3 — earned, ongoing (aim: 1–2 a month)**

- **Write up each case study as its own page.** Right now "Client Work" is a modal
  on the home page — it has no URL, so it cannot rank and cannot be linked to.
  Giving each project a real route like `/work/kulhad-chai-pizza` would give you a
  page per client, each one targeting that client's town and trade. This is the
  single biggest content opportunity in the codebase, and the route table in
  `src/seo/site.js` is already shaped to accept them.
- Write plainly useful posts in Bengali and English: "What GST billing software
  actually needs to do for a West Bengal shop", "What a restaurant menu website
  should cost in 2026". Local-language technical content has almost no competition.
- Answer questions on Reddit (r/india, r/kolkata, r/IndiaTech) and Quora as
  yourself, helpfully, without dropping links. The profile link is the point.
- Local press and business associations — the Bardhaman district chamber, local
  news covering small-business digitisation. A single local news mention is worth
  more than fifty directory submissions.

**Never do these:** buy links, use a "1000 backlinks for ₹500" service, swap links
in bulk with unrelated sites, post your URL into blog comments, or spin the same
guest post across many sites. All of them are detectable and all of them are worse
than having no links.

### D. What to watch, and when

- **Week 1:** Search Console verified, sitemap submitted, Business Profile started.
- **Week 2–3:** check Search Console → Pages. You want `https://ezentixlabs.com/`
  under "Indexed". If it sits in "Discovered – currently not indexed" past week 4,
  that is the rendering problem, and prerendering is the fix.
- **Month 2:** you should rank #1 for "eZentix Labs". If you do not, something is
  structurally wrong — check Search Console for manual actions.
- **Month 3+:** watch Search Console → Performance for which queries you *are*
  appearing for, and write pages aimed at those. Do not guess at keywords when
  Google will tell you.

Run [PageSpeed Insights](https://pagespeed.web.dev/) against the live URL after
deploying. The changes in Part 1 should put you in good shape, but measure the
real thing, not localhost.
